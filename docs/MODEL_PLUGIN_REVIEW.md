# 按“完整方法框架”复查模型接入

本轮专门检查“开发者接好自己的模型后，能否复用同一套提示词搜索、剪层、恢复、评估、选择和导出流程”。这是既定交付范围，不能用 OFT 单独跑通代替通用接口检查。

## 找到并修复的断点

| 之前的问题 | 当前行为 |
|---|---|
| `--backend-config` 拒绝自定义插件 | JSON 字段传给插件构造函数；原始参数与有效配置随搜索记录保存，导出复用同一组参数 |
| 通用提示词解析默认落到 LIBERO Object | 未显式指定时，按插件声明匹配提示词中的任务名，否则使用插件默认任务；多个任务要求明确选择 |
| 自定义插件的 preflight 早于任务绑定 | 先确定 `active_suite`，再执行 preflight |
| 模拟 agent 写死 32 层、OFT 层号和假设的结果 | 按当前层数和恢复菜单枚举未测方案；不声称固定方案已取得某个实测结果 |
| 插件数组只转换，不验证 | 检查所有 `0..n_layers` 边界、样本对齐、维度和有限数值；框架不据此宣称物理语义正确 |
| 插件可以返回另一个恢复配方的分数 | 和请求配方不一致的结果记录为失败 |
| `finalize` 只支持 OFT | 增加模型自己的 native exporter 接口；统一校验胜出记录并调用正确 exporter；生成校验清单和 selection receipt |
| 未实现导出可能靠手工猜权重 | 明确拒绝缺少 exporter、空产物、软链接和不合格 winner，不套用 OFT 格式 |

## 本轮实际验证

- **89 项回归通过。** 新增非 OFT 维度的探针、配置、搜索反馈、导出、错误路径和校验值检查。
- **外部插件完整衔接通过。** 在不含 torch 的 CPU venv 安装最终 wheel，把插件复制到框架源码之外，在 `/tmp` 运行。配置是 6 层、自定义 `custom_bench`、3 步动作块、4 维动作。两个 synthetic 候选完成搜索和反馈，同一条 `finalize` 命令成功导出，文件检查通过。
- **真实 OFT 兼容检查通过。** 新的共享接口验证实际加载 OFT-7B，采集 33 个 residual 边界、两个动作块，并运行 dense 与第 22 层 knockout，动作均为 `(2,8,7)`。
- **打包与隔离检查通过。** wheel 构建、屏蔽模型依赖的 CPU 演示、91 个 OFT 集成文件核对、候选路径及凭据扫描通过；原实验源文件哈希未变。

机器可读证据见 [model_plugin_validation.json](../provenance/model_plugin_validation.json)。外部插件使用已有 simulator，导出文件明确标为 synthetic plan；它不代表第二种真实机器人架构，也没有进行第二种真实架构的性能或动作等价性验证。

此前真实 OFT 的两条搜索、恢复、物理导出和独立动作对照证据仍归档在 [FRAMEWORK_ACCEPTANCE.md](FRAMEWORK_ACCEPTANCE.md)，该报告里的 75 项测试是当时版本的历史数量。本轮增加共享接口检查，不将之前的 GPU 结果自动标成新版本重跑了全部训练和评估。

用户随后报告在另一个服务器复用原环境验证 `761b676`：75 项通过、直接剪层及两步恢复均自动导出和独立重载、动作误差均 0.0、单次任务均 0/1。它是独立用户报告，未审阅原始产物，也不属于从零 GPU 安装验证或论文性能结果。

## 对开发者的交付含义

新架构需要适配四个模型操作；若要使用统一导出，再提供该架构的 native saver。适配完成后不需要重写 agent、探针公式、搜索算法、评估反馈和选择逻辑。接入步骤及可执行示例见 [ADDING_A_MODEL.md](ADDING_A_MODEL.md)。

不能把“适配自己的模型”描述为框架缺少通用性；也不能把“有接口、模拟接入通过”说成“所有真实模型都已验证”。当前真实模型证据是 OFT，其他模型保持声明的参考组件范围。

# 完整框架工程验收（2026-10-24）

本轮已实际接通“安装 → 加载 → 实时探针 → LLM 搜索 → teacher 缓存 → 恢复训练 → 仿真评估 → 反馈再搜索 → 自动选择 → 物理导出 → 独立重载”。范围是核心框架和 OFT 完整样例。StarVLA/FastWAM 保持参考组件范围。

这是小预算软件验收。恢复只训练两步、每个方案只测一个任务的一次 episode；两次恢复方案均未成功完成任务。不能据此声称恢复性能达标或复现论文。机器可读结果及原始记录哈希见 [framework_acceptance.json](../provenance/framework_acceptance.json)。

## 修复了哪些整条流程的问题

1. **真实入口报错。** 校准参数检查误放进模型加载函数，造成 `NameError`；已移回所属入口并补测试。
2. **环境里藏着旧配置。** LIBERO 目录缺资源、主目录配置指向旧项目；现在前置检查实际资源，每次调用写独立配置。
3. **模型服务返回格式不稳定。** 数值字段返回文字或输出被截断；统一决策格式校验、错误反馈和显式 token/timeout 配置。原始用户请求现已完整传给 agent。
4. **默默替换实验。** 不支持的恢复名字曾被换成菜单首项；现在明确拒绝，可用 `--recoveries` 限定预算允许的方案。
5. **小测试漏掉真模型计算规模。** 4096 维探针在线性求解上耗时过大；改用已有的等价对偶解法，并与原解法做数值对照，保留原指标定义。来源与验证见 [实现决策](../provenance/implementation_decisions.md)。
6. **训练到导出靠手工衔接。** 增加按胜出记录导出和独立动作核对的正式命令，核对恢复组件的 mask、step 和瓶颈尺寸，避免拿错权重。
7. **实验残留混入支持范围。** 从正式 evaluator 去掉 CIVR、LoRA/ORAR/task-module 等无关实验入口及三个不再依赖的模块。日志、缓存、权重和视频留在运行目录，不放进发布源码。
8. **配置只解析、没执行。** 不支持的多 suite 单次搜索和按小时限训现在明确报错。有效参数保存到 `request.json`，不会声称已执行这些未实现约束。

## 使用者怎么跑

完整安装步骤见 [NEW_SERVER.md](NEW_SERVER.md)，配置示例见 [README](../README.md)。新模型按 [ModelPlugin 接入说明](ADDING_A_MODEL.md) 配置；框架不会要求开发者重新实现我们的搜索方法。

搜索后直接运行：

```bash
python -m autoprune.finalize --run runs/search_RUN_ID --destination exports/oft-object
python -m autoprune.verify_oft_export --exported exports/oft-object \
  --suite libero_object --samples 2 --evaluate --run-root runs
```

保留本次配置、结果、导出清单和核对报告。不要提交 API key、完整实验日志、cache 或模型权重。小预算通过之后，再按自己的数据和模型设置进行完整训练、所有任务评估及独立最终评估。

# 这次开源提供什么

我们发布 AutoPruner 方法，并用 OFT 提供完整使用示例。同时发布 OFT Object 剪枝权重。其他模型和训练数据由使用者按上游说明准备。

| 内容 | 本仓库提供 | 验证边界 |
|---|---|---|
| 核心框架 | agent 搜索、probe、恢复调度、评测反馈、结果选择与记录 | CPU 测试及 OFT 小预算真实链路；性能范围见验收记录 |
| OFT 完整示例 | 固定依赖、自定义补丁、加载、恢复、评测、物理导出 | 本机及用户独立服务器完成工程验收；论文数字复现另行核对 |
| StarVLA 参考 | 实验实现中的剪层和边界 adapter 代码、已核实的论文设置 | 未完成候选版本的 GPU 验证；不提供现成训练入口 |
| FastWAM 参考 | 固定上游上的 MoT 剪层补丁、已核实的论文设置 | 补丁应用检查通过；未完成候选版本的 GPU 验证 |
| 其他模型 | `ModelPlugin` 接口、可执行的模拟接入示例 | 提供可配置接口及统一导出调度；开发者适配模型操作，已做非 OFT 维度的模拟验证 |

## 哪些东西需要自己准备

1. 获取相应模型代码及合法可用的权重、数据，建立该模型需要的环境。
2. OFT 按 [新服务器指南](NEW_SERVER.md) 操作。新模型按 [接入说明](ADDING_A_MODEL.md) 写一个插件。
3. 在自己的 checkpoint 和评测设置下测量 dense baseline，再运行搜索。示例中的论文数字不能替代这一步。

换模型通常需要少量模型代码适配，不能承诺只换一个模型名字就能运行。我们自己的剪层、adapter 和 agent 方法实现随仓库公开。

## 为什么没有整份搬运另外两个模型项目

原始 StarVLA/FastWAM 目录混有实验和运行环境改动。尤其 FastWAM 本机 trainer 与所固定的上游存在较大的接口及训练流程差异，整份覆盖会连带回退其他逻辑。因此目前只提取有明确边界的组件；没有把尚未核实的训练组合包装成已支持的后端。

参考代码的来源、哈希、修改记录在 `examples/source_manifest.json`。论文设置中的 `null` 表示尚未确认，不用当前默认参数补写历史。完整复现这两个模型的论文结果，仍需补齐对应训练与评测集成；这些参考组件不等同于复现完成。

## 日志、cache 和临时配置怎么处理

历史日志和 checkpoint 留在实验目录。公开仓库只放运行所需源码、配置模板和经过整理的结果索引。每次使用者运行产生的日志、probe、teacher 缓存和经验库放入自己的 `runs/`，不随源码提交、不自动跨运行复用。路径、设备、模型服务凭据由参数或明确列出的环境变量提供。

公开源码从审查后的文件清单构建，不包含原实验仓库的 Git 历史。

通用接口的本轮复查和验证范围见 [MODEL_PLUGIN_REVIEW.md](MODEL_PLUGIN_REVIEW.md)。
